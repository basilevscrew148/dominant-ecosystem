# Глава 16. Доминанта в LLM и prior art на GitHub

## Доминанта уже «внутри» LLM

Механизм внимания трансформера — **мягкая доминанта**: attention-веса дают одним токенам приоритет (суммация) и подавляют другие (торможение). Один «господствующий очаг» контекста формируется на каждом слое.

Но у LLM нет двух вещей из протокола доминанты:

- **инерции между вызовами** — каждый вызов заново строит внимание; цель не «переживает» шаги сама;
- **антиципаторного горизонта** — модель не держит «целевое состояние» как явный объект.

Именно поэтому протокол доминанты добавляется **на уровне агента**: цель и хронотоп выносятся в явный контекст и переживают шаги.

## Prior art на GitHub: паттерн, а не ниша

Проверено поиском (web_search + GitHub). Итог: **прямой реализации «доминанты Ухтомского» как скилла/плагина нет** — это свободная ниша. Но сам паттерн «метод мыслителя → инструмент» массовый:

| Мыслитель | Реализация |
|---|---|
| Луман (Zettelkasten) | PKM-er/obsidian-zettelkasten-navigation; Dyldog/luhman-obsidian-plugin |
| де Боно (шесть шляп) | juanallo/six-hats-skill; debono-thinking-hats; six-thinking-hats (для тестирования) |
| автономное исследование | assafelovic/gpt-researcher |

**Вывод:** новизна экосистемы «Доминанта» — не в паттерне (он зрелый), а в **его применении к доминанте** как единому протоколу: фокус + торможение + инерция + хронотоп + собеседник + мета-наблюдение. Ни один из перечисленных проектов не кодирует этот *набор* целиком.

## Математическая граница

Строгой обучаемой модели доминанты нет; есть качественная модель Крюкова (доминанта + компаратор гиппокампа, фазовый переход) [DOI 10.1007/s11055-005-0049-6] и гипотеза Radchenko (доминанта = precision-weighting + хронотоп) [DOI 10.5281/zenodo.19347980]. Формализация доминанты как обучаемого агента — открытая задача (см. главу 20).

## Итог

LLM уже «доминантен» внутри, но не между вызовами; экосистема добавляет недостающее (инерцию, цель, собеседника) на уровне агента. На GitHub это не занято — ниша свободна и обоснована.
